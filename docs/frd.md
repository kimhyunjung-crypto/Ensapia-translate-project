# ENSAPIA Slack 비즈니스 메시지 AI 번역 워크벤치 기능정의서

상태: 완료

> 기능정의서(FRD)는 “사용자가 무엇을 누르면, 서비스가 무엇을 처리하고, 화면에 무엇을 보여줘야 하는지”를 정리한 약속이다. 개발 용어는 처음 나올 때 쉬운 말로 함께 설명한다.

## ⓪ 먼저 보는 범위 요약

- **필수 하위 기능:** 54개
- **1차 기능 범위:** 54개 전체 포함으로 확정
- **예상 개발 작업 규모:** 큼
- **복잡한 이유:** 번역 한 건에 ChatGPT·Gemini 번역, 양쪽 교차검토, 최종 종합, 품질검사, 저장과 비용 계산이 이어진다.
- **사용자 화면:** 번역, 용어집, 인명·호칭, 운영 설정의 네 화면
- **초기 사용자:** 로그인 없이 한 명

실제 개발 작업은 이 54개에 초기 세팅, 데이터 구조 만들기, 화면 마무리와 테스트가 더해지므로 더 많아진다.

### 범위를 줄인다면 이 순서로 검토

사용자가 모든 기능을 1차 버전에 넣기로 확정했다. 아래는 일정이 부족할 때만 다시 검토할 후보다.

1. **F3.6 용어 파일 가져오기** — 빼면 용어를 한 건씩 등록해야 한다.
2. **F6.4~F6.6 비용 상세** — 빼면 월 총액과 사용 한도 경고만 남는다.
3. **F5.2~F5.4 문체 규칙 직접 관리** — 빼면 처음 준비한 말투 규칙만 사용할 수 있다.

## ① 서비스 요약

사용자는 한국어 또는 일본어 Slack 메시지를 원문 입력란 하나에 붙여 넣고 `번역하기`를 누른다. 프로그램은 먼저 언어를 판단하고 원문에서 회사 용어, 인명·호칭과 상황별 말투 규칙을 찾아 반드시 지킬 기준으로 고정한다. 그 뒤 ChatGPT와 Gemini가 같은 원문과 규칙으로 각각 번역하고 서로의 결과를 검토해 하나의 최종 번역을 만든다. 사용자는 중간 과정 없이 최종 번역만 확인하고 복사한다.

### 이번에 확정한 내용

- 문체 규칙 관리, 용어 파일 가져오기, 수정·비활성화, 실패 재시도, 비용 상세, 비용 경고와 저장 데이터 삭제를 모두 1차 버전에 포함한다.
- 원문은 공백과 줄바꿈을 포함해 최대 3,000자까지 입력할 수 있다.
- 번역 기준이 겹치면 인명·호칭, 회사 용어, 상황별 말투, AI 일반 판단 순서로 적용한다.
- 번역 데이터는 자동 삭제하지 않으며 사용자가 기간을 선택해 직접 삭제한다.
- AI 호출 전에 프로그램이 원문을 바꾸지 않은 채 인명·호칭·회사 용어·말투 규칙을 찾아 고정하며, 두 AI에 같은 원문과 규칙 목록을 전달한다.
- 인명·호칭 등록에는 양방향 대표 표기를 모두 저장한다.
  - 한국어→일본어: `이시와타리 대표님`, `이시와타리상`, `이시와타리님` → `石渡さん`
  - 일본어→한국어: `石渡さん` → `이시와타리님`

## ② 전체 기능 목록

`필수`는 1차 버전에 반드시 만드는 기능이다. 괄호 안의 화면은 그 기능을 어디에서 시작하는지를 뜻한다.

### F1. 번역 화면 — 필수 7개

- **F1.1 [필수] 원문 입력** — 한국어 또는 일본어 Slack 메시지를 붙여 넣거나 직접 작성한다. (진입: 번역 화면)
- **F1.2 [필수] 입력 확인** — 원문이 비어 있거나 공백·줄바꿈을 포함해 3,000자를 넘으면 이유를 알려주고 실행하지 않는다. (진입: 번역 화면)
- **F1.3 [필수] 언어와 방향 자동 판단** — 한국어면 일본어로, 일본어면 한국어로 방향을 정한다. (진입: 번역 화면)
- **F1.4 [필수] 번역 실행과 진행 표시** — `번역하기`를 누르면 중복 실행을 막고 `번역 중` 상태 하나만 보여준다. (진입: 번역 화면)
- **F1.5 [필수] 최종 번역 표시** — 모델별 중간 결과를 숨기고 최종 번역 하나만 보여준다. (진입: 번역 화면)
- **F1.6 [필수] 최종 번역 복사** — 버튼 한 번으로 최종 번역을 복사하고 완료 알림을 보여준다. (진입: 번역 화면)
- **F1.7 [필수] 실패 안내와 다시 시도** — 실패한 경우 성공처럼 표시하지 않고 원문을 유지한 채 다시 시도할 수 있게 한다. (진입: 번역 화면)

### F2. 화면 뒤의 규칙 적용과 AI 번역 과정 — 필수 8개

- **F2.1 [필수] 사전 규칙 검색과 표기 고정** — AI를 호출하기 전에 프로그램이 원문에서 등록된 인명·호칭·회사 용어·말투 규칙을 찾는다. 문장 전체를 미리 번역하거나 원문을 바꾸지 않고 반드시 쓸 표기, 피할 표기와 필요한 어조를 목록으로 만든다. 규칙이 겹치면 인명·호칭 → 회사 용어 → 상황별 말투 → AI 일반 판단 순서로 적용한다. (진입: 번역 화면)
- **F2.2 [필수] 번역 조건 묶기** — 사용자가 입력한 원문과 F2.1의 규칙 목록을 하나의 번역 조건으로 묶어 두 AI에 똑같이 전달한다. (진입: 번역 화면)
- **F2.3 [필수] ChatGPT 1차 번역** — 같은 조건으로 첫 번째 번역을 만든다. (진입: 번역 화면)
- **F2.4 [필수] Gemini 1차 번역** — ChatGPT와 동시에 독립적인 번역을 만든다. (진입: 번역 화면)
- **F2.5 [필수] ChatGPT 교차검토** — Gemini 결과와 비교해 오역·누락·말투를 고친다. (진입: 번역 화면)
- **F2.6 [필수] Gemini 교차검토** — ChatGPT 결과와 비교해 미번역 문구·용어·자연스러움을 고친다. (진입: 번역 화면)
- **F2.7 [필수] 최종 종합** — 두 번역과 두 검토 결과를 바탕으로 최종 번역 하나를 만든다. (진입: 번역 화면)
- **F2.8 [필수] 마지막 품질검사** — 의미, 숫자, 고유명사, 말투, 누락과 목표 언어가 아닌 문장이 남았는지 확인하고 F2.1의 고정 표기가 지켜졌는지 검사한다. (진입: 번역 화면)

### F3. 회사 용어 관리 — 필수 8개

- **F3.1 [필수] 용어 목록 보기** — 원어, 권장 표기, 설명과 사용 상태를 본다. (진입: 용어집 화면)
- **F3.2 [필수] 검색과 조건 보기** — 용어나 설명을 검색하고 활성 항목만 골라 본다. (진입: 용어집 화면)
- **F3.3 [필수] 새 용어 등록** — 원어, 권장 표기, 언어 방향, 설명, 금지 표기와 상태를 입력한다. (진입: 용어집 화면)
- **F3.4 [필수] 용어 수정** — 기존 용어의 표기와 설명을 고친다. (진입: 용어집 화면)
- **F3.5 [필수] 사용 중지·다시 사용·미사용 항목 삭제** — 번역에 사용한 적이 없는 용어는 완전히 삭제할 수 있다. 한 번이라도 사용된 용어는 결과 추적을 위해 남겨 두고 번역 적용만 끄거나 다시 켠다. (진입: 용어집 화면)
- **F3.6 [필수] 용어 파일 가져오기** — 정해진 표 형식의 파일로 여러 용어를 한꺼번에 등록한다. (진입: 용어집 화면)
- **F3.7 [필수] 잘못된 입력과 중복 확인** — 필수값과 같은 용어가 이미 있는지 확인한다. (진입: 용어집 화면)
- **F3.8 [필수] 번역 적용과 변경 기록** — 활성 용어를 모든 AI 단계에 적용하고 언제 무엇을 바꿨는지 남긴다. (진입: 용어집 화면)

### F4. 인명·호칭 관리 — 필수 8개

- **F4.1 [필수] 인명·호칭 목록 보기** — 통합 표기, 인식 표현 수와 사용 상태를 본다. (진입: 인명·호칭 화면)
- **F4.2 [필수] 한국어 인식 표현 여러 개 입력** — Enter 또는 쉼표로 `이시와타리상` 같은 표현을 태그로 추가한다. (진입: 새 멤버 창)
- **F4.3 [필수] 일본어 통합 표기 입력** — 여러 한국어 표현이 바뀔 일본어 결과 하나를 입력한다. (진입: 새 멤버 창)
- **F4.4 [필수] 한국어 통합 표기 입력** — 일본어 원문을 한국어로 바꿀 때 사용할 결과 하나를 입력한다. (진입: 새 멤버 창)
- **F4.5 [필수] 양방향 변환 미리보기** — 저장하기 전에 각 표현이 어떻게 바뀌는지 확인한다. (진입: 새 멤버 창)
- **F4.6 [필수] 인명·호칭 수정** — 등록된 인식 표현과 통합 표기를 고친다. (진입: 인명·호칭 화면)
- **F4.7 [필수] 사용 중지·다시 사용·미사용 항목 삭제** — 번역에 사용한 적이 없는 규칙은 완전히 삭제할 수 있다. 한 번이라도 사용된 규칙은 결과 추적을 위해 남겨 두고 번역 적용만 끄거나 다시 켠다. (진입: 인명·호칭 화면)
- **F4.8 [필수] 중복 확인과 번역 적용** — 같은 인식 표현의 중복을 막고 활성 규칙을 모든 AI 단계에 적용한다. (진입: 새 멤버 창)

### F5. 상황별 말투 관리 — 필수 6개

- **F5.1 [필수] 말투 규칙 목록 보기** — 인사, 요청, 거절, 사과, 독촉, 확인과 감사 규칙을 본다. (진입: 운영 설정)
- **F5.2 [필수] 새 말투 규칙 등록** — 상황, 권장 어조, 쿠션어, 피해야 할 표현과 예문을 입력한다. (진입: 운영 설정)
- **F5.3 [필수] 말투 규칙 수정** — 기존 표현과 예문을 고친다. (진입: 운영 설정)
- **F5.4 [필수] 사용 중지·다시 사용·미사용 항목 삭제** — 번역에 사용한 적이 없는 규칙은 완전히 삭제할 수 있다. 한 번이라도 사용된 규칙은 결과 추적을 위해 남겨 두고 적용만 끄거나 다시 켠다. (진입: 운영 설정)
- **F5.5 [필수] 입력 확인** — 같은 상황 규칙이 겹치거나 필수값이 빠졌는지 확인한다. (진입: 운영 설정)
- **F5.6 [필수] 번역 적용과 변경 기록** — 활성 규칙을 모든 AI 단계에 적용하고 변경 내용을 기록한다. (진입: 운영 설정)

### F6. AI 연결·비용·저장 설정 — 필수 10개

- **F6.1 [필수] AI 연결 상태 확인** — ChatGPT와 Gemini가 요청을 받을 수 있는지 보여준다. (진입: 운영 설정)
- **F6.2 [필수] 모델과 프롬프트 버전 확인** — 현재 사용하는 AI 모델과 번역 지시문 버전을 보여준다. (진입: 운영 설정)
- **F6.3 [필수] 확정 모델 운영 설정** — 1차 번역·교차검토에는 GPT-5.6 Luna와 Gemini 3.7 Flash를 사용하고, 최종 종합은 GPT-5.6 Luna가 담당한다. (진입: 운영 설정)
- **F6.4 [필수] 번역 한 건의 사용량과 비용** — 번역 한 번에 사용한 호출 수, 글자 처리량과 예상 비용을 계산한다. (진입: 운영 설정)
- **F6.5 [필수] 일별·월별 사용량** — 날짜와 월 단위로 사용량과 비용을 합쳐 보여준다. (진입: 운영 설정)
- **F6.6 [필수] 공식 단가로 예상 비용 계산** — 저장된 사용량에 각 회사의 확정 단가를 적용한다. (진입: 운영 설정)
- **F6.7 [필수] 월 비용 한도 설정** — 한 달 동안 사용할 최대 예상 비용을 정한다. (진입: 운영 설정)
- **F6.8 [필수] 비용 경고와 실행 확인** — 한도에 가까워지거나 넘으면 번역 전에 알려주고 계속할지 묻는다. (진입: 번역 화면)
- **F6.9 [필수] 저장 정책 확인** — 무엇을 왜 저장하는지와 현재 접근 범위를 보여준다. (진입: 운영 설정)
- **F6.10 [필수] 기간별 번역 데이터 삭제** — 자동 삭제는 하지 않으며, 사용자가 기간을 선택하고 확인을 거쳐 원문·모델별 결과·교차검토 결과·최종 번역을 한꺼번에 지운다. (진입: 운영 설정)

### F7. 기록과 안전장치 — 필수 7개

- **F7.1 [필수] 번역 전체 과정 자동 저장** — 원문, 두 1차 번역, 두 교차검토, 최종 번역과 사용 기준을 저장한다. (진입: 번역 화면)
- **F7.2 [필수] 작업 상태와 오류 기록** — 호출 시간, 성공·실패, 오류 종류와 다시 시도 여부를 기록한다. (진입: 번역 화면)
- **F7.3 [필수] 적용 기준 버전 기록** — 어떤 용어·인명·말투와 AI 설정을 사용했는지 남긴다. (진입: 각 관리 화면)
- **F7.4 [필수] 저장 정보 보호** — 저장 내용을 암호화하고 초기 사용자만 접근하게 한다. (진입: 운영 설정)
- **F7.5 [필수] 원문 속 명령문 무시** — 원문을 시스템 지시로 실행하지 않고 번역 대상 글로만 취급한다. (진입: 번역 화면)
- **F7.6 [필수] 저장 실패 구분** — 번역 실패와 저장 실패를 구분해 알리고 필요한 기록을 다시 저장한다. (진입: 번역 화면)
- **F7.7 [필수] 삭제 기록 남기기** — 언제 어떤 기간의 데이터를 지웠는지 남기되 삭제한 원문 자체는 기록에 남기지 않는다. (진입: 운영 설정)

## ③ 대표 사용 장면

### 장면 1 — Slack 메시지 번역

- **시작 조건:** 사용자가 번역 화면을 열었고 두 AI가 연결되어 있다.
- **정상 흐름:** 원문 입력 → 번역하기 → 언어 자동 판단 → 프로그램의 규칙 검색·표기 고정 → 같은 원문과 규칙으로 두 AI 번역·교차검토 → 품질검사 → 최종 번역 표시 → 복사
- **대표 예외:** 한 AI가 실패하거나 최종 품질검사를 통과하지 못하면 성공으로 표시하지 않고 다시 시도 버튼을 보여준다.
- **완료 기준:** 최종 번역 하나가 표시되고 복사할 수 있으며 전체 처리 결과가 저장된다.
- **데이터 변화:** 번역 작업, 모델 결과, 적용 규칙, 사용량, 비용과 오류 기록이 추가된다.
- **사용자가 보는 결과:** 원문, 통합 진행 상태, 최종 번역, 복사 또는 오류·재시도만 본다.

### 장면 2 — 인명·호칭 기준 등록

- **시작 조건:** 사용자가 인명·호칭 화면에서 `새 멤버`를 누른다.
- **정상 흐름:** 한국어 인식 표현 여러 개 입력 → 일본어 통합 표기 입력 → 한국어 통합 표기 입력 → 양방향 미리보기 → 저장
- **대표 예외:** 같은 한국어 인식 표현이 이미 등록되어 있으면 중복된 항목을 알려주고 저장하지 않는다.
- **완료 기준:** 새 카드가 목록에 나타나고 다음 번역부터 양방향 규칙이 적용된다.
- **데이터 변화:** 인명·호칭 규칙과 변경 시각이 저장된다.
- **사용자가 보는 결과:** `이시와타리님 ↔ 石渡さん`처럼 양방향 변환 예시를 확인한다.

## ⑥ 화면에는 보이지 않지만 필요한 기능

- 두 AI 호출을 가능한 한 동시에 시작해 기다리는 시간을 줄인다.
- 사전 규칙 적용은 별도 AI를 호출하지 않고 프로그램 내부에서 처리한다.
- 사전 규칙 적용 중에는 사용자가 입력한 원문을 직접 바꾸지 않고, AI에 함께 전달할 별도의 규칙 목록만 만든다.
- 한 단계가 실패하면 어느 단계인지 구분한다.
- AI 응답이 약속한 형식인지 검사한다.
- 목표 언어가 아닌 문장이 남았는지 검사한다.
- 숫자, 부정 표현과 고유명사가 빠지지 않았는지 검사한다.
- 저장할 때 사용한 모델·프롬프트·용어·인명·문체 버전을 함께 남긴다.
- 비용 계산에 필요한 모델별 사용량을 저장한다.
- 데이터 삭제 후에는 원문을 남기지 않고 삭제 사실만 기록한다.

## ⑦ 자동으로 적용할 안전 기준

구체적인 구현 방법은 다음 기술 설계 단계에서 정한다.

- API 키(ChatGPT와 Gemini에 접속하기 위한 비밀 열쇠)는 화면이나 코드에 그대로 노출하지 않는다.
- 원문과 모델 결과는 저장할 때 암호화한다.
- 외부 AI에는 번역에 필요한 정보만 전달한다.
- 원문에 적힌 명령은 실행하지 않고 번역할 글로만 취급한다.
- 번역 버튼을 여러 번 눌러 같은 작업이 중복 생성되지 않게 한다.
- 오류 기록에 API 키나 불필요한 원문 전체가 남지 않게 한다.
- 개발·테스트에서는 실제 회사 메시지나 실제 개인정보를 사용하지 않는다.
- 키보드만으로도 주요 기능을 이용하고 글자와 버튼의 색 대비를 확보한다.

## ⑧ 모든 화면의 공통 동작 규칙

- 필수 입력이 비어 있으면 해당 입력칸 바로 아래에 쉬운 이유를 표시한다.
- 저장이나 번역 중에는 같은 버튼을 다시 누를 수 없게 한다.
- AI 작업이 실패하면 해당 단계만 자동으로 한 번 다시 시도한다.
- 자동 재시도도 실패하면 원문을 유지하고 사용자가 누를 수 있는 `다시 시도` 버튼을 보여준다.
- 오류가 생겨도 사용자가 입력한 원문과 작성 중인 값은 사라지지 않는다.
- 성공하면 무엇이 저장되거나 복사됐는지 짧게 알려준다.
- 같은 용어나 인명 표현이 있으면 기존 항목을 알려주고 중복 저장하지 않는다.
- 사용 중지된 기준은 목록에는 남지만 새 번역에는 적용하지 않는다.
- 여러 기준이 같은 표현에 걸리면 인명·호칭, 회사 용어, 상황별 말투, AI 일반 판단 순서로 적용한다.
- 두 AI에는 변경되지 않은 같은 원문과 동일한 사전 규칙 목록을 전달한다.
- 번역에 사용한 적이 없는 용어·인명·문체 규칙만 완전히 삭제할 수 있다.
- 한 번이라도 번역에 사용된 기준은 완전히 삭제할 수 없고 사용 중지 또는 재활성화만 할 수 있다.
- 삭제는 대상과 기간을 다시 보여주고 사용자가 확인한 뒤 실행한다.
- 번역 데이터는 시간이 지났다는 이유만으로 자동 삭제하지 않는다.
- 기간별 번역 데이터를 삭제하면 원문과 모든 중간·최종 번역문을 지우고, 원문이 없는 사용량·비용 합계와 삭제 사실만 남긴다.
- 원문은 공백과 줄바꿈을 포함해 3,000자까지 입력할 수 있으며, 초과하면 현재 글자 수와 제한을 함께 알려준다.
- 월 예상 비용이 한도의 80%에 도달하면 경고하고, 100%부터는 번역마다 실행 확인을 받는다.
- 초기 버전은 한 명만 사용하며 로그인·계정 메뉴를 제공하지 않는다.
- PC 화면을 우선하고 모바일에서는 입력과 결과를 위아래로 배치한다.

## ⑨ 사용자가 눈으로 확인할 완료 기준

- 한국어 원문을 입력하면 일본어 최종 번역 하나가 나타난다.
- 일본어 원문을 입력하면 한국어 최종 번역 하나가 나타난다.
- 원문이 3,000자를 넘으면 번역이 시작되지 않고 현재 글자 수와 최대 글자 수가 표시된다.
- 번역 중에는 ChatGPT·Gemini의 중간 결과가 화면에 보이지 않는다.
- 사전 규칙 적용 과정도 화면에 따로 표시하지 않고 하나의 `번역 중` 상태 안에서 처리된다.
- 최종 번역을 버튼 한 번으로 복사할 수 있다.
- 번역 실패 시 원문이 유지되고 `다시 시도` 버튼이 나타난다.
- 한 AI 단계가 일시적으로 실패하면 해당 단계만 자동으로 한 번 다시 실행된다.
- 새 용어를 등록·수정·사용 중지·재활성화할 수 있다.
- 정해진 파일 형식으로 여러 용어를 한꺼번에 등록할 수 있다.
- `이시와타리 대표님`, `이시와타리상`, `이시와타리님`이 모두 `石渡さん`으로 변환된다.
- `이시와타리 대표님`이 일반 용어의 `대표님` 규칙과 겹쳐도 인명·호칭 설정인 `石渡さん`이 우선 적용된다.
- `이시와타리 대표님`이 포함된 원문은 변경되지 않은 상태로 두 AI에 전달되며, 두 AI 모두 `石渡さん`을 반드시 사용하라는 같은 규칙을 받는다.
- `石渡さん`이 등록한 한국어 통합 표기 `이시와타리님`으로 변환된다.
- 인명·호칭 규칙을 수정·사용 중지·재활성화할 수 있다.
- 상황별 말투 규칙을 등록·수정·사용 중지·재활성화할 수 있다.
- 번역에 사용한 적이 없는 용어·인명·문체 규칙은 확인 후 완전히 삭제할 수 있다.
- 한 번이라도 번역에 사용된 기준에는 완전 삭제 대신 사용 중지 버튼만 제공된다.
- 번역 한 건, 하루와 한 달의 사용량과 예상 비용을 확인할 수 있다.
- 비용 한도에 가까워지면 번역 전에 경고가 나타난다.
- 월 비용 한도 100% 이후에는 사용자가 확인해야만 번역이 실행된다.
- 기간을 선택하고 확인한 뒤 저장된 번역 데이터를 일괄 삭제할 수 있다.
- 보관 기간이 지나도 번역 데이터가 자동으로 삭제되지 않는다.
- 기간별 삭제 후에는 해당 원문·모델 결과·교차검토 결과·최종 번역문을 다시 조회하거나 복구할 수 없다.
- 화면을 새로고침해도 저장된 용어·인명·문체 기준이 사라지지 않는다.
- 두 AI 중 하나가 실패하면 전체 번역을 성공으로 표시하지 않는다.
